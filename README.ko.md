# ImageMarker 사용 설명서

**R2R TFT 소자 이미지를 확인하고 키보드로 판정 라벨을 기록하는 Windows 프로그램**

이 설명서는 **ImageMarker 2.0.0**의 동작을 기준으로 작성했습니다. 문서 기준일은 **2026-09-30**입니다. 메뉴와 버튼은 화면에서 찾기 쉽도록 영문 이름을 그대로 적었습니다.

[HTML 설명서](README.ko.companion.html) · [English](README.md) · [구현 명세](docs/SPEC.md) · [변경 이력](CHANGELOG.md)

## 1. 어떤 일을 하는 프로그램인가

R2R 공정으로 인쇄한 TFT를 검토할 때는 소자 이미지와 전기적 측정값을 함께 보면서 각 소자의 상태를 기록해야 합니다. 이미지 파일을 하나씩 열고 Excel에서 같은 소자의 행을 찾는 작업을 줄이려고 만든 프로그램이 ImageMarker입니다.

소자별로 잘라 둔 RGB 이미지를 불러오면 화면 위쪽에는 이미지가, 아래쪽에는 소자 위치와 측정값이 나타납니다. 검토자는 이미지를 보고 키 하나로 라벨을 붙입니다. Excel을 연결했다면 수정한 라벨을 원본 파일의 `Status` 열에 저장하고 이미지 폴더만 있는 경우에는 결과를 CSV로 저장할 수 있습니다.

- 많은 소자의 외관을 순서대로 확인하면서 `GOOD`, `BAD`, `OPEN`으로 분류합니다.
- 기존 라벨과 이미지를 대조하여 잘못된 판정을 수정합니다.
- `ON`, `OFF`, `ON/OFF`, `gm`, `Vth`, `Carrier Mobility`를 참고하며 검토합니다.
- 실험별로 정한 라벨 세트를 공유하고 같은 이름과 단축키로 작업합니다.
- 후속 분석이나 학습 데이터 준비에 사용할 라벨 CSV를 만듭니다.

**판정은 사람이 합니다.** 이 프로그램에는 AI 자동 분류, 모델 학습, TFT 측정, 원본 TIFF 분할 기능이 없습니다. 이미지 분할과 측정은 먼저 끝내야 하며 ImageMarker는 준비된 이미지와 데이터를 연결해 라벨을 검토하는 단계에 사용합니다. 전기적 지표도 새로 계산하지 않고 파일에 저장된 값을 보여줍니다.

## 2. 처음 사용한다면: 작업 순서

1. **이미지 준비** — 소자별 RGB PNG 파일과, 있으면 측정 Excel 파일을 준비합니다.
2. **폴더 열기** — `Load Folder`에서 이미지 폴더를 선택합니다. 하위 폴더도 함께 읽습니다.
3. **라벨 세트 확인** — `Labels`에서 사용할 분류와 단축키를 확인합니다. 새 설정의 기본값은 `GOOD / BAD / OPEN`입니다. CSV 라벨은 활성 세트를 기준으로 읽으므로 먼저 선택합니다.
4. **데이터 연결** — Excel에 기록하려면 `Open Excel...`을 누르고 샘플 이름을 연결합니다. 기존 CSV를 사용할 때는 `Load CSV`를 선택합니다.
5. **이미지 검토** — 행 하나를 선택하고 `G`, `B`, `O`로 판정합니다. `↑`와 `↓`로 이동하고 잘못 지정했으면 `←`로 저장 기준값을 복원합니다.
6. **결과 저장** — Excel 작업은 `Save to Excel`, CSV 작업은 `Save CSV`를 사용합니다. 저장 메시지와 `Unsaved` 개수를 확인합니다.

Excel을 최종 결과물로 쓴다면 **Excel 저장을 먼저 끝낸 뒤** CSV를 추가로 내보내세요. 현재 버전에서 `Save CSV`는 Excel을 갱신하지 않으면서도 미저장 표시를 해제합니다. 자세한 내용은 10절에 설명했습니다.

## 3. 설치와 실행

### 설치 파일 또는 실행 파일이 있는 경우

`ImageMarker-Setup-2.0.0.exe`를 전달받았다면 설치한 뒤 시작 메뉴의 ImageMarker를 엽니다. 기본값은 사용자별 설치이며 바탕 화면 바로가기는 선택 사항입니다. 모든 사용자용 설치를 고르면 관리자 권한이 필요할 수 있습니다.

독립 실행 파일 `ImageMarker.exe`를 전달받았다면 바로 실행합니다. 이 두 방식에서는 Python을 별도로 설치할 필요가 없습니다. 저장소의 소스 코드 ZIP에는 빌드한 실행 파일이 반드시 포함되는 것은 아닙니다.

### Python 소스로 실행하는 경우

Windows와 Python 3.9 이상이 필요합니다. Python에 Tkinter가 포함되어 있어야 하며 실행 라이브러리는 `pillow`와 `openpyxl`입니다. 저장소를 내려받은 폴더에서 PowerShell을 열고 실행합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

가상환경의 실행 파일 경로를 직접 지정하므로 PowerShell의 스크립트 실행 정책을 바꿀 필요가 없습니다. `python` 명령을 찾지 못하면 Python 설치 상태를 확인하거나 첫 줄에서 설치된 런처 `py`를 사용하세요. 프로그램 버전은 `Help → About`에서 확인합니다.

## 4. 입력 파일 준비

### 이미지 이름과 폴더 구조

```text
<name>_rgb_<row>_<node>.png

예: sample_sam1_rgb_01_07.png
    name = sample_sam1, Row = 1, Node = 7
```

`name`은 샘플을 구별하는 이름이고 `row`와 `node`는 소자 위치를 나타내는 정수입니다. `01`과 `1`은 같은 위치로 처리합니다. `_rgb_`와 확장자는 대소문자를 구분하지 않습니다. JPG, TIFF, IR 이미지와 이 형식에 맞지 않는 PNG는 목록에 들어오지 않습니다.

```text
measurement-day/
  sample_sam1_slices/
    sample_sam1_rgb_01_01.png
    sample_sam1_rgb_01_02.png
  sample_sam2_slices/
    sample_sam2_rgb_01_01.png
    sample_sam2_rgb_01_02.png
```

위 구조에서는 `measurement-day`를 선택하면 두 샘플을 한 번에 읽습니다. `_slices`라는 폴더 이름은 관례이며 필수 조건이 아닙니다. `_slice_manifest.json`도 요구하지 않습니다.

실험 데이터에 흔히 쓰는 **26행 × 38개 = 988개 소자**는 데이터 구성의 예입니다. 프로그램이 이 크기나 150 × 150 픽셀만 허용하는 것은 아닙니다. 실제로 발견된 이미지를 목록에 넣으며 빠진 위치를 자동으로 채우지 않습니다.

같은 `(name, row, node)`가 여러 경로에 있으면 정렬된 폴더·파일 순서로 먼저 발견한 한 장만 사용합니다. 건너뛴 수는 정보 표시줄의 `duplicate(s) skipped`로 확인합니다. 재검토용 사본을 같은 상위 폴더 아래에 두었다면 중복 여부를 먼저 확인하세요.

### Excel 파일

입력 형식은 `.xlsx`입니다. **첫 번째 워크시트**를 읽으며 열 이름은 **첫 번째 행**에 있어야 합니다. 화면에는 시트를 선택하는 기능이 없습니다.

| 구분 | 열 이름 | 용도 |
|---|---|---|
| 필수 | `Name`, `Row`, `Node`, `Status` | 샘플과 소자를 찾고 라벨을 읽거나 저장 |
| 선택 | `ON`, `OFF`, `ON/OFF`, `gm`, `Vth`, `Carrier Mobility` | 표에 측정값 표시 |
| 기타 | 전압별 스윕 데이터 등 | 표에 표시하거나 직접 수정하는 대상이 아님 |

열 순서는 고정되어 있지 않습니다. 열 이름 앞뒤 공백과 대소문자는 무시하지만 `Carrier Mobility` 같은 이름 내부의 표기는 맞춰야 합니다. `Row`와 `Node`는 숫자 또는 `01` 같은 숫자 문자열을 사용할 수 있습니다. 위치를 숫자로 해석하지 못하는 행은 읽기에서 제외됩니다.

동일한 `(Name, Row, Node)`는 한 번만 나타나도록 준비하세요. 중복 행이 있으면 먼저 읽은 행을 사용합니다. `Status`는 비어 있어도 되고 현재 라벨 세트에 없는 값도 읽습니다. 측정값의 단위는 원본 데이터의 정의를 따르며 앱에서 단위를 변환하지 않습니다.

## 5. 화면 읽는 법

![ImageMarker 2.0.0 메인 화면. 합성 샘플 데이터로 구성한 예시입니다.](assets/screenshot.png)

위 화면은 기능 설명을 위한 합성 샘플입니다. 실제 TFT의 판정 예시나 측정 결과가 아닙니다.

| 영역 | 표시 내용과 조작 |
|---|---|
| 상단 이미지 | 현재 소자의 RGB 이미지를 창 크기에 맞춰 원래 비율로 표시 |
| 이미지와 표 사이 구분선 | 위아래로 끌어 이미지 또는 표 영역 확대 |
| 파일 도구 모음 | 폴더·Excel·CSV 열기와 저장 |
| 라벨 버튼 줄 | 활성 라벨과 단축키, `Revert`, `Clear`; 마우스로도 판정 가능 |
| 데이터 표 | 이미지 이름에서 얻은 `Name`, 위치, 측정값, `Status`; 행 선택과 정렬 |
| `*` 표시 | 저장 기준값과 다른 라벨. 저장하거나 기준값으로 되돌리면 사라짐 |
| 정보 표시줄 | 현재 위치, 상태별 개수, 폴더, 데이터 파일, `Unsaved` 개수 |

표의 `Name`은 이미지 파일에서 얻은 이름입니다. 연결한 Excel `Name`으로 바꾸지 않습니다. 라벨을 지정하면 이미지 위에 약 1초 동안 문구가 나타나고 행 색과 라벨 버튼 색은 활성 라벨 세트를 따릅니다.

측정값은 표시 공간에 맞춰 반올림하거나 지수 형식으로 보여줍니다. 화면 표시 방식일 뿐 원본 측정값을 바꾸지는 않습니다. 이미지 확대는 창과 구분선 크기에 따라 이루어지며 별도의 배율 조절이나 이미지 편집 기능은 없습니다.

## 6. Excel과 이미지를 연결하고 저장하기

### 폴더와 Excel 열기

먼저 `Load Folder`로 이미지를 읽은 뒤 `Open Excel...`에서 측정 파일을 선택합니다. 이미지 없이 Excel부터 열면 폴더를 먼저 불러오라는 메시지가 나옵니다.

### 샘플 이름 연결하기

`Match samples to Excel names` 창에서 이미지 샘플마다 대응하는 Excel `Name`을 선택합니다. 두 파일의 이름이 완전히 같을 필요는 없습니다.

```text
이미지: sample_SAM 1_rgb_01_07.png
          ↓ 샘플 이름 연결: SAM 1 ↔ sam1
Excel:   Name = measurement_sam1, Row = 1, Node = 7
          ↓ 해당 소자의 행
결과:    측정값과 Status를 읽고, 수정한 Status를 같은 행에 저장
```

프로그램은 `sam1`, `SAM 1`, `sam_1`에서 샘플 번호를 추출합니다. 같은 번호를 가진 Excel 이름이 **정확히 하나**일 때만 자동으로 제안합니다. 측정 날짜나 인쇄 조건까지 검증하지는 않으므로 제안된 이름을 직접 확인하세요. 번호가 없거나 후보가 여러 개면 드롭다운에서 직접 고릅니다.

대응하는 데이터가 없는 샘플은 `(skip)`으로 둡니다. 서로 다른 샘플을 실수로 같은 Excel `Name`에 연결하지 않도록 확인하세요. `OK`를 누르면 각 샘플 안에서 `Row`와 `Node`가 같은 행을 찾아 연결합니다.

### 연결 결과 확인하기

완료 창에는 샘플별 `matched`와 `without data`, 전체 개수가 나타납니다. 연결 대상으로 선택한 Excel `Name` 중 이미지가 없는 행 수도 표시합니다. 예상한 소자 수와 맞는지 확인한 뒤 라벨링을 시작합니다.

연결되지 않은 이미지와 `(skip)` 샘플은 측정값과 라벨이 빈 상태로 남습니다. 별도의 미연결 표시 열은 없으므로 **연결 결과 창의 개수를 확인해야 합니다.** 측정값이 빈칸이라는 사실만으로 연결 실패를 단정할 수는 없습니다. 원본 측정값 자체가 비어 있을 수도 있습니다.

### 라벨 검토와 저장

라벨을 지정한 다음 `Save to Excel` 또는 `Ctrl+S`를 누릅니다. Excel이 연결되어 있고 변경한 라벨이 있어야 저장 버튼이 활성화됩니다. 변경한 행에 Excel 저장 위치가 있으면 저장합니다. 필터로 숨긴 행도 같은 조건으로 저장합니다.

`measurement.xlsx`를 처음 수정할 때는 같은 폴더에 `measurement.backup.xlsx`를 만든 뒤 원본에 저장합니다. 백업 파일이 이미 있으면 덮어쓰지 않습니다. 백업은 매번 갱신되는 최신 사본이 아니라 **처음 만들어진 시점의 파일**입니다.

앱이 값 변경을 요청하는 셀은 `Status`뿐입니다. 다만 저장할 때 `openpyxl`이 통합문서를 다시 쓰므로 파일 전체가 바이트 단위로 그대로 유지된다는 뜻은 아닙니다. 일반 셀·수식·서식 보존은 기존 테스트로 확인하지만 모든 Excel 확장 기능의 보존을 보장하지는 않습니다. 매크로 통합문서 `.xlsm`은 지원 대상이 아닙니다.

이미지와 연결되지 않은 행에는 새 Excel 행을 만들지 않습니다. 변경했지만 저장할 곳이 없는 라벨은 건너뛰며 결과 창에 건너뛴 수가 표시되고 `Unsaved`에 남습니다. 이 라벨도 보관하려면 **Excel에 연결된 변경부터 저장한 뒤 `Save CSV`로 전체 결과를 따로 남기세요.**

### 작업 중 원본 파일을 편집해야 할 때

프로그램은 읽을 때 기억한 워크시트 행·열 위치로 저장합니다. **연결해 둔 원본 Excel의 행을 정렬·삽입·삭제하거나 열 배치를 바꾸지 마세요.** 다른 사람이 같은 파일을 수정한 경우에도 작업을 정리하고 새 구조의 파일을 다시 열어 연결해야 합니다. 동시 편집 충돌을 감지하는 기능은 없습니다.

## 7. 라벨과 키보드 단축키

### 기본 라벨: GOOD / BAD / OPEN

| 라벨 | 키 | 기본 색 | 외관 검토에 사용할 때의 의미 |
|---|---|---|---|
| `GOOD` | `G` 또는 `1` | 초록 | 외관상 정상으로 판단한 소자 |
| `BAD` | `B` 또는 `2` | 빨강 | 번짐, 브리징, 정렬 불량 등 인쇄 결함으로 판단한 소자 |
| `OPEN` | `O` 또는 `3` | 주황 | 전극이나 채널의 누락·단절이 보이는 소자 |

이는 기본 라벨 설명을 풀어 쓴 안내입니다. 프로그램이 결함을 판별하거나 전기적 합격 여부를 보증하지 않습니다. `BAD`와 `OPEN`의 경계, 애매한 소자의 처리 방법은 실험 담당자가 작업 전에 정해야 합니다.

### 다른 기본 제공 라벨 세트

| 라벨 세트 | 키와 저장되는 값 |
|---|---|
| `PASS / FAIL` | `P` 또는 `1` → `PASS`, `F` 또는 `2` → `FAIL` |
| `Electrical (legacy 1.x)` | `1` → `Pass`, `2` → `No Active`, `3` → `No Gate Effect`, `4` 또는 `→` → `Open`, `5` → `Short` |

예전 단축키를 쓰려면 `Labels → Electrical (legacy 1.x)`를 선택합니다. **2.0 기본 세트의 `3`은 `OPEN`, 전기적 세트의 `3`은 `No Gate Effect`입니다.** 기본 세트에는 `→` 라벨 키가 없습니다.

숫자 표는 기본 옵션을 기준으로 합니다. 숫자 순서 선택을 끄면 직접 등록된 숫자 키만 작동합니다. 사용자 정의 세트에서는 직접 등록한 키가 순서 선택보다 우선합니다.

### 공통 조작

| 키 또는 버튼 | 동작 |
|---|---|
| `↑` / `↓` | 현재 목록에서 1행 이동 |
| `Ctrl+↑` / `Ctrl+↓` | 10행 이동 |
| `Shift+↑` / `Shift+↓` | 100행 이동 |
| `Page Up` / `Page Down` | 1000행 이동 |
| `←` 또는 `Revert` | 선택한 행의 라벨을 저장 기준값으로 복원 |
| `0`, `Delete` 또는 `Clear` | 라벨을 빈칸으로 변경 |
| `Ctrl+O` | 이미지 폴더 열기 |
| `Ctrl+S` | Excel에 저장. CSV 저장 단축키가 아닙니다. |
| `Ctrl+L` | 라벨 세트 편집기 열기 |

`Revert`는 직전 키 입력을 한 단계씩 취소하는 기능이 아닙니다. Excel·CSV를 읽었을 때의 라벨로 돌아갑니다. 앱에서 저장에 성공했다면 마지막 저장 성공 시점의 라벨로 돌아갑니다. 이미지 폴더만 읽은 직후의 기준값은 빈칸입니다.

문자 단축키는 대소문자를 구분하지 않습니다. 한글 입력 상태에서 예상대로 동작하지 않으면 영문 입력으로 전환한 뒤 라벨 버튼이나 `Help → Keyboard shortcuts`에 표시된 키를 사용하세요.

## 8. 라벨 세트를 바꾸거나 공유하기

### 편집기로 수정하기

1. `Labels → Edit label set...` 또는 `Ctrl+L`을 누릅니다.
2. `Set name`에 세트를 구분할 이름을 적습니다.
3. `Add`와 `Remove`로 라벨을 추가하거나 지웁니다. 세트에는 **1~9개** 라벨을 둘 수 있습니다.
4. 라벨을 선택하여 `Name`, `Colour`, `Description`을 수정합니다. **라벨의 `Name`이 Excel의 `Status`나 CSV의 `label`에 기록됩니다.**
5. `Add key...`를 누르고 원하는 키를 직접 누릅니다. 한 라벨에 여러 키를 등록할 수 있고 `Remove key`로 지웁니다.
6. `Up`과 `Down`으로 순서를 바꾸고 `OK`로 적용합니다.

프리셋을 수정하면 사용자 정의 세트가 됩니다. 기본 제공 프리셋은 남아 있으므로 메뉴에서 다시 고를 수 있습니다. 세트 변경만으로 기존 라벨을 일괄 변환하지 않습니다. 예를 들어 `Pass`를 읽은 뒤 기본 세트를 골라도 기존 값은 `GOOD`으로 바뀌지 않습니다. 활성 세트에 없는 값은 그대로 표시되고 행은 기본 배경색으로 보입니다.

라벨 이름은 대소문자를 무시했을 때 중복될 수 없고 서로 다른 라벨에 같은 키를 등록할 수 없습니다. `↑`, `↓`, `Page Up`, `Page Down`, `←`, `0`, `Delete`, `Esc`, `Enter`, `Tab`, `Space`, `Backspace`는 예약 키입니다. `Ctrl` 조합을 사용자 라벨 키로 지정하는 방식은 지원하지 않습니다.

`Digit keys 1-9 select labels in order`를 켜면 별도로 등록되지 않은 숫자가 세트 순서를 따릅니다. **직접 등록한 숫자 키가 우선**입니다. 세 번째 라벨에 `1`을 등록하면 `1`은 세 번째 라벨을 지정합니다. 혼동을 줄이려면 숫자는 순서 선택에 맡기고 사용자 단축키는 문자로 지정하세요. 순서 옵션을 꺼도 직접 등록한 숫자 키는 남습니다.

### 자동 이동

`Auto-advance to next row after labeling`을 켜면 한 행에 라벨을 적용한 뒤 다음 행으로 이동합니다. 기본값은 꺼짐입니다. 단일 행에서는 같은 라벨을 다시 누르거나 `Clear`를 사용해도 이동합니다. 여러 행을 선택한 경우와 `Revert`에는 자동 이동을 적용하지 않습니다.

필터가 켜져 있으면 라벨 변경으로 행이 목록에서 빠질 때 선택이 먼저 조정될 수 있습니다. 자동 이동까지 적용되어 다음에 볼 행이 예상과 달라질 수 있으므로 일부 상태만 검토할 때는 자동 이동을 끄고 현재 위치를 확인하는 편이 좋습니다.

### JSON으로 공유하기

`Export label set...`으로 활성 세트를 JSON에 저장하고 다른 PC에서 `Import label set...`으로 불러옵니다. 세트와 라벨의 이름·색상·키·설명을 공유하며 이미지나 판정 결과는 포함하지 않습니다.

```json
{
  "schema_version": 1,
  "name": "GOOD / BAD / OPEN",
  "labels": [
    {"name": "GOOD", "color": "#2e9e4f", "keys": ["g"], "description": "외관상 정상"},
    {"name": "BAD", "color": "#d64545", "keys": ["b"], "description": "인쇄 결함"},
    {"name": "OPEN", "color": "#e8a33d", "keys": ["o"], "description": "누락 또는 단절"}
  ]
}
```

바깥쪽 `name`은 세트 이름이고 `labels` 안의 각 `name`이 실제 저장할 라벨입니다. 색은 `#RRGGBB`, 키는 `g`, `Right`, `F5` 같은 Tkinter 키 이름을 사용합니다. 직접 JSON을 쓰기보다는 편집기에서 설정한 뒤 내보내는 방식이 편합니다.

활성 세트, 숫자 순서 선택, 자동 이동 옵션은 `%APPDATA%\ImageMarker\config.json`에 저장됩니다. 이 파일은 **설정만** 보관합니다. 이미지 폴더, 현재 행, 필터, 미저장 판정을 복구하는 세션 파일이 아닙니다. 다음 실행에서는 폴더와 저장한 Excel 또는 CSV를 다시 열어야 합니다. 테스트용 설정 폴더는 `IMAGEMARKER_CONFIG_DIR` 환경변수로 분리할 수 있습니다.

## 9. 필터·정렬·여러 행 선택

`Status filter`는 **현재 데이터에 실제로 있는 라벨**과 `(blank)`를 나열합니다. 세트의 모든 이름을 미리 보여주는 목록은 아닙니다. `All`은 전부 표시하고 `None`은 전부 숨깁니다. 여기서 `None`은 라벨을 지우라는 뜻이 아닙니다.

필터를 적용하면 표, 방향키 이동, `Image n/m` 위치 표시가 보이는 목록을 기준으로 바뀝니다. 파일을 삭제하거나 필터 결과만 저장하는 기능은 아닙니다. 상태별 개수는 필터 적용 중에 `표시된 수/전체 수`로 나타납니다.

라벨을 수정하면 필터를 즉시 다시 적용합니다. 새 값이 꺼진 항목에 해당하면 행이 사라질 수 있습니다. **처음 등장하는 라벨은 체크된 상태로 추가되므로** `(blank)`만 검토하려는 경우에도 새 라벨을 처음 붙인 뒤에는 필터를 다시 확인하세요.

열 제목을 누르면 오름차순·내림차순으로 정렬합니다. 보고 있던 소자의 선택은 유지되고 이후 이동은 정렬된 순서를 따릅니다.

`Ctrl+클릭`으로 여러 행을 고르거나 `Shift+클릭`으로 범위를 선택하면 라벨 키와 `Clear`, `Revert`가 **선택한 모든 행**에 적용됩니다. 이미지 창은 여러 이미지를 동시에 보여주지 않습니다. 일괄 적용 전에 선택 범위를 확인하고 한 소자만 수정할 때는 행 하나를 다시 클릭하세요.

## 10. Excel 저장과 CSV 저장의 차이

| 항목 | Save to Excel | Save CSV |
|---|---|---|
| 결과 파일 | 연결한 원본 `.xlsx` | 저장 창에서 지정한 `.csv` |
| 대상 | 변경한 행 중 Excel과 연결된 행 | 불러온 **모든 이미지 행** |
| 필터의 영향 | 숨겨진 변경 행도 저장 | 숨겨진 행도 내보냄 |
| 기록 내용 | 대상 셀의 `Status` | `name,row,node,label`과 CSV에서 읽어 둔 추가 열 |
| 자동 백업 | 첫 쓰기 전에 `.backup.xlsx` 1회 | 없음 |
| 미저장 표시 | Excel에 쓸 수 있는 변경 행만 해제 | 전체 행 해제 |

### Excel 작업 중 CSV도 필요한 경우

**`Save to Excel` → 저장 결과 확인 → `Save CSV`** 순서로 진행하세요. `Save CSV`는 Excel에 쓰지 않으면서 모든 행의 저장 기준값을 갱신합니다. CSV를 먼저 저장하면 Excel은 예전 라벨을 갖고 있어도 `Unsaved: 0`이 표시됩니다. 이어서 Excel 저장을 눌러도 변경 사항이 없다는 메시지가 나올 수 있습니다.

이 상황에서는 저장한 CSV를 보관하세요. 원본 Excel에는 CSV의 라벨을 소자별로 대조해 다시 적용해야 합니다. 이 프로그램에는 CSV를 Excel에 자동 반영하는 별도 가져오기 기능이 없습니다.

### CSV만 사용하는 경우

이미지 폴더를 열고 바로 라벨링한 뒤 `Save CSV`로 새 파일을 만들어도 됩니다. 기존 파일을 이어서 검토하려면 **라벨 세트를 먼저 선택하고** `Load CSV`를 누릅니다.

```csv
name,row,node,label
sample_sam1,1,1,GOOD
sample_sam1,1,2,BAD
sample_sam1,1,3,OPEN
sample_sam1,1,4,
```

이미지와 CSV의 `(name, row, node)`가 일치해야 연결됩니다. Excel처럼 이름을 고르는 창은 없으므로 `name`은 이미지 이름의 접두사와 정확히 맞춰야 합니다. 위치의 앞자리 0은 무시합니다. 헤더는 대소문자와 앞뒤 공백을 무시하며 라벨 열은 `label`, `marker`, `status`를 읽습니다. 저장할 때는 `label`로 출력합니다.

같은 키가 중복되면 나중 CSV 행의 값을 사용합니다. CSV에서 읽은 추가 열은 해당 이미지 행과 함께 다시 저장하지만 **이미지가 없는 CSV 행은 내보내지 않습니다.** Excel에서 표시한 측정값이 자동으로 CSV 추가 열로 변환되는 것도 아닙니다. 원본 CSV를 보존하려면 다른 이름으로 저장하세요.

`Load CSV`는 겹치는 행을 덮어씁니다. CSV에 없는 이미지 행의 이전 라벨·측정값은 남을 수 있으므로 독립된 CSV 작업을 시작할 때는 `Load Folder`로 폴더를 새로 연 뒤 CSV를 불러오세요. CSV를 열면 기존 Excel 연결은 해제됩니다.

활성 세트에 맞는 값은 그 세트의 표기로 읽습니다. 기본 세트에서 `good`은 `GOOD`이 됩니다. 예전 별칭인 `1` → `Pass`, `-1` → `Open`, `ok` → `Pass`는 그 대상 라벨이 세트에 있을 때만 적용합니다. 빈칸과 `NONE`, `N/A`, `NA`, `AMBIGUOUS`, `UNKNOWN`, `UNCLASSIFIED`는 CSV에서 라벨 없음으로 읽으므로 사용자 라벨로 쓰지 마세요. CSV는 UTF-8 BOM 형식으로 저장합니다.

## 11. 저장 기준값과 종료할 때의 확인

라벨이 저장 기준값과 다르면 행과 창 제목에 `*`가 표시되고 `Unsaved`가 늘어납니다. 원래 값으로 되돌리면 저장하지 않아도 `*`가 사라집니다. 단축키를 누른 사실 자체가 변경 이력으로 남지는 않습니다.

창을 닫거나 다른 폴더·데이터를 열 때 미저장 값이 있으면 다음을 묻습니다.

| 선택 | 의미 |
|---|---|
| `Yes` | 현재 방식으로 먼저 저장한 뒤 진행 |
| `No` | 미저장 변경을 버리고 진행 |
| `Cancel` | 현재 작업 화면에 머무름 |

Excel이 연결되어 있으면 `Yes`는 Excel에 저장하고 그렇지 않으면 CSV 저장 창을 엽니다. **Excel과 연결되지 않은 이미지의 변경값은 종료 창의 `Yes`로 보관되지 않습니다.** 현재 버전은 이런 행을 건너뛴 뒤에도 종료하거나 다음 파일로 넘어갈 수 있습니다. 종료 전에 `Save to Excel` 결과의 건너뛴 수를 확인하고 필요한 라벨은 CSV로 남기세요.

별도의 자동 저장, 작업 세션 복원, 단계별 실행 취소 기록은 없습니다. 설정 저장과 판정 결과 저장은 다른 기능입니다.

## 12. 자주 겪는 문제

| 현상 | 확인할 내용과 조치 |
|---|---|
| `No valid RGB images found` | PNG 이름 형식을 확인합니다. 빈 폴더를 열려고 시도한 뒤에는 원래 유효한 폴더를 다시 열어 화면을 갱신하세요. |
| 예상보다 이미지가 적음 | 이름 형식에 맞지 않는 파일과 중복 키를 확인하고 `duplicate(s) skipped` 수를 봅니다. |
| Excel 필수 열 오류 | 첫 시트 첫 행에 `Name`, `Row`, `Node`, `Status`가 있는지 확인합니다. |
| 샘플이 자동 연결되지 않음 | `sam` 번호가 없거나 후보가 여러 개인지 확인하고 이름을 직접 선택합니다. |
| `without data`가 많음 | 선택한 Excel `Name`, Row·Node, 이미지와 측정 파일의 샘플 범위를 확인합니다. |
| 측정값이 빈칸임 | 열이나 값이 없는지, 숫자로 해석되는지 확인합니다. 수식은 Excel에서 계산 후 저장된 결과가 있어야 표시됩니다. |
| Excel 저장 버튼이 비활성임 | Excel 연결과 변경값 여부를 확인합니다. `Load CSV` 이후에는 Excel 연결이 해제됩니다. |
| `File locked` 또는 권한 오류 | Excel에서 파일을 닫고 폴더 쓰기 권한을 확인한 뒤 다시 저장합니다. |
| 기대한 라벨이 입력되지 않음 | 활성 세트와 직접 등록한 키를 확인합니다. 1.x와 2.0 기본 세트는 숫자 키 의미가 다릅니다. |
| 수정한 행이 사라짐 | 필터에서 새 라벨이 제외되었는지 확인하고 `All`로 전체를 표시합니다. |
| 표가 비어 있음 | 필터에서 `None`을 선택했는지 확인하고 `All`을 누릅니다. |
| CSV를 저장했는데 Excel이 그대로임 | 두 저장 방식은 별개입니다. 10절의 저장 순서와 복구 설명을 따릅니다. |
| `Failed to load image` | PNG가 손상되었거나 이동·삭제되었는지 확인합니다. |
| 설정이 기본값으로 돌아옴 | `%APPDATA%\ImageMarker\config.json` 접근과 내용을 확인합니다. 읽지 못하면 기본값을 사용합니다. |

문제를 전달할 때는 프로그램 버전, 라벨 세트, 오류 문구, 파일 이름 형식, 연결 결과 개수를 함께 적으면 원인을 찾기 쉽습니다. 실제 측정 파일을 공유하기 어렵다면 같은 헤더와 몇 개의 가상 행으로 재현해 보세요.

## 13. 반복 작업 예시

**기존 Excel 판정을 외관으로 재검토:** 이미지 폴더 → Excel 연결 → 샘플별 연결 수 확인 → 세트 선택 → 이미지와 측정값 검토 → `Save to Excel` → 필요하면 `Save CSV`.

**이미지에 처음 라벨 붙이기:** 이미지 폴더 → 기본 세트 또는 팀의 JSON 세트 선택 → 단일 행으로 검토 → 필요하면 자동 이동 켜기 → `Save CSV`. 다음 작업에서는 같은 이미지 폴더와 CSV를 다시 엽니다.

**1.x 데이터를 이어서 검토:** `Electrical (legacy 1.x)` 선택 → 이미지 폴더 → Excel 또는 CSV 연결 → 기존 `1`~`5`, `→`로 검토 → 원래 작업 방식으로 저장. 세트 변경만으로 과거 라벨 문자열은 바뀌지 않습니다.

여러 사람이 나누어 검토한다면 같은 라벨 세트 JSON과 판정 기준을 공유하되 입력·출력 파일은 각자 구분해서 관리하세요. 동시 편집이나 여러 사람의 결과 자동 병합은 지원하지 않습니다.

## 14. 개발·배포 및 설명서 갱신

이 절은 실행 파일을 직접 만들거나 문서를 관리할 때 사용합니다. 일반 검토 작업에는 필요하지 않습니다.

### 테스트

```powershell
.\.venv\Scripts\python.exe -m pip install pytest
.\.venv\Scripts\python.exe -m pytest -q
```

데이터 모델, Excel·CSV 처리, 라벨 세트와 UI 기본 동작을 검사합니다. UI 테스트는 Tkinter 창을 만들 수 없는 환경에서는 건너뛸 수 있습니다. 테스트에는 합성 데이터와 임시 파일을 사용합니다.

### Windows 실행 파일과 설치 파일 만들기

```powershell
.\build.bat
.\build_installer.bat
```

첫 명령은 `.venv`를 만들거나 재사용하여 실행 의존성과 PyInstaller를 설치하고 `dist\ImageMarker.exe`를 만듭니다. 두 번째 명령은 기존 실행 파일로 `dist\ImageMarker-Setup-2.0.0.exe`를 만듭니다. 설치 파일 빌드에는 **Inno Setup 6 또는 7**의 `ISCC.exe`가 필요합니다. `PATH`를 먼저 확인한 뒤 일반적인 사용자별·전체 사용자 설치 위치에서 컴파일러를 찾습니다.

### Markdown과 HTML 함께 갱신하기

한국어 원본은 `README.ko.md`, 영어 설명서는 `README.md`, 구현 명세는 `docs/SPEC.md`입니다. HTML은 이 파일에서 생성하여 같은 폴더의 `*.companion.html`로 저장합니다. 문서 생성에는 **Python 3.10 이상**이 필요하므로 아래 명령을 실행할 가상환경도 이 버전으로 만드세요.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-docs.txt
.\.venv\Scripts\python.exe scripts/build_docs.py
.\.venv\Scripts\python.exe scripts/build_docs.py --check
```

HTML은 본문과 화면 이미지를 파일 안에 포함하므로 파일 하나만으로도 인터넷 연결 없이 읽을 수 있습니다. 다른 HTML 설명서로 이동하려면 동봉된 문서의 폴더 구조를 유지하세요. Markdown에서 화면 이미지를 보려면 `assets/screenshot.png`도 함께 보관해야 합니다. 브라우저의 인쇄 기능으로 PDF나 종이 출력도 가능합니다. 문서 생성용 패키지는 앱 실행 의존성과 분리되어 있습니다.
